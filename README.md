# Hopline · 代理 + 订阅面板

> **Hopline —— 部署在 Cloudflare Workers / Pages 的 VLESS / XHTTP 代理与订阅面板，拆成两个互相独立的脚本**：
> - **`Hopline-proxy.js`（代理）**：只做一件事——在节点路径上接收 VLESS（WebSocket / XHTTP）并转发；没有面板、登录与订阅；环境变量只有 `PATH` 与 `NODE_KEY` 两项，UUID 与运行设置由面板通过签名的 HTTPS 控制接口下发；内置落地 / 出站代理与可配置的地区反代。
> - **`Hopline-panel.js`（面板 + 订阅）**：图形化面板与订阅生成——优选域名与在线优选 IP 来源、ECH 加密、地区 / 运营商 / IP 版本多维筛选，输出 Clash / Sing-box 等各客户端格式；面板页面与 Clash 模板都内嵌在脚本里。
>
> 面板与代理之间只有一条 **HTTPS**：面板保存代理的**域名、节点路径与密钥**，用密钥给请求签名，由面板生成 UUID 并下发给代理、启停代理、修改代理的设置。没有服务绑定，所以两个 Worker 可以在不同的 Cloudflare 账号里。

## 一、功能概览

| 脚本 | 功能 | 说明 |
|---|---|---|
| 代理 | **多协议** | VLESS 的 WebSocket 与 XHTTP 两种传输始终同时启用，没有开关 |
| 代理 | **落地与出站** | 反代 / 落地 IP（填写后作为固定出口优先使用）+ 出站代理（SOCKS5 / HTTP(S) / Shadowsocks）+ 出站模式（默认 / 直连优先 / 仅走代理）；直连与出站都不通时由地区反代兜底 |
| 代理 | **地区反代** | 直连不通时使用：内置（按 Worker 机房自动选，可固定首选 / 次选地区）/ 仅使用自己的反代列表 / 关闭 |
| 代理 | **控制接口** | 节点路径下由密钥派生的一条签名 HTTPS 入口（不知道密钥就找不到；任何不合规请求都返回与其它路径相同的 `Hello World !`）：面板用它下发 UUID、启用 / 停用代理、读写下面的出站 / 地区反代设置、读取状态（在线、版本、配置问题与非敏感的设置摘要）。UUID 与设置保存在代理自己的 KV `NODE_KV` 里（必须绑定） |
| 代理 | **路径伪装** | 只有节点路径上的 WebSocket 升级与 XHTTP POST 进入代理，其余一律返回 `Hello World !` 页面；面板还没有下发 UUID，或代理被停用时，节点路径上也一样只返回这个页面 |
| 面板 | **图形化面板** | 仪表盘 / 节点配置 / 优选配置 / 面板设置 / 关于项目，保存即生效，主题默认跟随系统，也可一键切换日间 / 夜间（见「四、面板使用」） |
| 面板 | **代理管理** | 「面板设置 → 代理」保存代理列表（域名、节点路径、密钥、UUID、启用开关）：一键「连接并同步」（自动生成 UUID 并下发）、「更换 UUID」（旧 UUID 在代理上再保留 10 分钟）、**停用 / 启用**（停用后订阅不再下发它，代理也只显示 `Hello World !`）；「代理设置」页在线修改代理的反代 / 落地 IP、出站代理、出站方式与地区反代；仪表盘显示代理是否在线与版本。可以添加多个代理（最多 8 个），**订阅合并所有启用的代理**：每个代理各出一套节点，节点名带「·代理名」后缀，总数仍封顶 500 并平均分给各代理 |
| 面板 | **协议下发** | VLESS / XHTTP 两种节点各自独立开关，决定订阅里下发哪些节点（代理本身始终两种都接受） |
| 面板 | **地址来源** | 原生地址、优选域名、在线优选 IP（HostMonit / uouin / 微测网 / 自定义 API），各自独立开关（见「五、地址来源与优选」） |
| 面板 | **地区与筛选** | 地区（全部 / 香港 / 台湾 / 美国 / 新加坡 / 日本 / 韩国 / 德国）+ IP 版本（IPv4 / IPv6）+ 运营商（移动 / 联通 / 电信）组合筛选；只剔除名称明确标记为未选项的节点，通用节点保留；筛选后为空时按 运营商 → IP 类型 → 地区 逐级放宽 |
| 面板 | **ECH 加密** | 自定义 ECH 域名 / ECH DNS（DoH），开启后自动进入仅 TLS 节点模式；链接类订阅与 Clash 订阅带 ECH 参数，Sing-box / Surge / Loon / Quantumult X 订阅不含 ECH |
| 面板 | **多客户端** | Clash / Mihomo、Sing-box、Surge、Loon、Quantumult X、v2rayN / Shadowrocket / Nekoray 等链接类客户端、Stash，按 UA 自动识别；订阅地址追加 `/clash`、`/stash`（同为 Clash 配置）、`/singbox`、`/surge`、`/loon`、`/quanx`、`/v2ray`、`/plain` 等后缀可强制指定格式 |
| 面板 | **安全** | 加盐摘要的管理密码、登录限速、会话自动失效、安全响应头、路径伪装（见「六、性能与安全」） |

### 节点下发规则

- **来源**：节点全部来自「原生地址（默认关）+ 优选域名 + 在线优选 IP」，IP 一律只保留 Cloudflare 段地址，不生成随机 IP，也不内置静态 IP 池
- **端口**：默认只下发 TLS 端口节点（「节点配置 → 仅 TLS 端口」）；关闭后每个 443 节点另追加一个 80 明文节点（名称带「·80」），来源自带的 8080 / 2052 等明文端口原样下发；自定义域名使用明文节点需在 Cloudflare 关闭「始终使用 HTTPS」；开启 ECH 时始终只下发 TLS 端口节点
- **XHTTP**：只出现在链接类与 Clash 订阅中；Sing-box / Surge / Loon / Quantumult X 没有 XHTTP 传输，一律不含。官方 sing-box 内核同样不支持 XHTTP
- **Sing-box**：生成 sing-box 1.12+ 格式配置（二进制 .srs 规则集经 jsDelivr 下载）；GUI.for.SingBox 请用其「导入 sing-box 配置」插件导入订阅
- **数量**：单次订阅最多 500 个节点（按免费计划 10ms CPU 限制设定），来源不足时按实际数量下发，不补足；不做轮询换新，来源数据不变时每次下发相同的节点

## 二、快速部署

> 全程约 10 分钟，需要两个文件（仓库根目录，已是构建好的成品，直接使用）：**[`Hopline-proxy.js`](https://raw.githubusercontent.com/iv7777/Hopline/main/Hopline-proxy.js)**（代理）和 **[`Hopline-panel.js`](https://raw.githubusercontent.com/iv7777/Hopline/main/Hopline-panel.js)**（面板）。两者各部署成一个独立的 Worker，可以放在同一个或不同的 Cloudflare 账号里。面板页面与 Clash 配置模板都内嵌在 `Hopline-panel.js` 里，运行时不需要访问 GitHub / jsDelivr。代理脚本另有混淆版 `obf_Hopline-proxy.js`（面板脚本没有混淆版）。

### 2.1 准备

- 一个 Cloudflare 账号（Workers / Pages）
- （推荐）一个自己的域名：`*.workers.dev` 域名可能被限制访问，且 XHTTP 协议要求**代理**绑定自定义域名

### 2.2 部署代理（`Hopline-proxy.js`）

1. 登录 Cloudflare 控制台 → **Workers 和 Pages** → **新建 Worker**，先用默认模板部署
2. 点「编辑代码」，**删除全部默认内容**，把 `Hopline-proxy.js` 全文粘贴进去，点「部署」
3. 进入该 Worker 的 **设置 → 变量**，添加两个**必填**变量：

   | 变量 | 填什么 |
   |---|---|
   | `PATH` | 节点路径，如 `mynode`（只能含字母、数字及 `. _ ~ -`） |
   | `NODE_KEY` | 控制密钥：至少 24 位的随机可见字符（建议设为加密 / Secret 类型）。面板用它给控制请求签名；也可以先在面板里点「生成密钥」得到一个再填到这里 |

   **UUID 不在环境变量里**：由面板生成并下发。落地 / 出站 / 地区反代等可选变量见「3.1 代理脚本的环境变量」。
4. **绑定 KV（必须）**：创建一个单独的 KV 命名空间，绑定到代理 Worker，**变量名 `NODE_KV`**（不要和面板的 `CONFIG_KV` 共用）。代理的 UUID、启用开关与在线设置都保存在里面；没有它代理不会为任何节点连接服务
5. 在该 Worker 的 **Domains & Routes**（域和路由）里添加你的自定义域名，类型选 **Custom Domain**（DNS 由 Cloudflare 托管时证书自动签发）。**这个域名就是面板里要填的「代理域名」**。面板通过它联系代理，所以必须是自定义域名，不能只用 `*.workers.dev`；面板与代理在同一个 zone 里时更要用 Custom Domain，否则 Cloudflare 会拒绝 Worker 之间的请求（错误 1042）
6. 代理没有任何页面：访问根路径和任何未知路径都只显示 `Hello World !`；`PATH` 或 `NODE_KEY` 缺失 / 不合法时所有请求返回 503 设置说明

### 2.3 部署面板（`Hopline-panel.js`）

1. 同样新建一个 Worker，粘贴 `Hopline-panel.js` 全文并部署
2. 在 **设置 → 变量** 添加两个**必填**变量：

   | 变量 | 填什么 |
   |---|---|
   | `PATH` | 面板与订阅的访问路径，如 `mypanel`（只能含字母、数字及 `. _ ~ -`，不能是 `login`、`version`）。与代理的节点路径互相独立 |
   | `ADMIN` | 管理密码（建议设为加密 / Secret 类型） |

3. 创建一个 **KV 命名空间**，在面板 Worker 里绑定，**变量名必须是 `CONFIG_KV`**。不绑定 KV 的话面板无法保存配置，也无法保存代理列表
4. （可选）给面板 Worker 也添加自定义域名
5. 访问 `https://面板域名/<PATH>`，用用户名 `admin`（默认）和 `ADMIN` 密码登录

面板与代理之间**不需要服务绑定**，两个 Worker 可以在同一个或不同的 Cloudflare 账号里。

### 2.4 在面板里添加代理

登录面板后，在 **面板设置 → 代理** 填入（可以添加多个代理：点列表里的一行编辑，「＋ 添加代理」新增；订阅会合并所有启用的代理，多个时每个代理各出一套节点，节点名带「·代理名」后缀，总数封顶 500 并平均分配。想临时不用某个代理，取消它的「启用」即可）：

| 面板里的字段 | 对应代理的 | 说明 |
|---|---|---|
| 代理域名 | 代理 Worker 的自定义域名 | 节点的 SNI / Host，也是面板联系代理的地址（只能是域名，不带端口 / 路径） |
| 节点路径 | 环境变量 `PATH` | 必须一致 |
| 密钥 | 环境变量 `NODE_KEY` | 必须一致；写入后不再回显，留空 = 保持不变；可以点「生成密钥」「复制」 |
| UUID | 无（保存在代理的 `NODE_KV`） | 留空即可：点「保存并连接」后面板生成并下发；代理上已经有 UUID（比如重新添加同一个代理）时会接管它，不会把客户端搞断 |
| 启用 | 无 | 取消勾选并保存 = 订阅里不再下发这个代理，并通知代理对外只显示 `Hello World !` |

按钮：**保存并连接**（保存并立即联系代理，缺 UUID 就生成并下发）、**连接并同步**（让代理与面板保存的一致：UUID、启用状态）、**更换 UUID**（新 UUID 立即生效，旧的在代理上保留 10 分钟，之后客户端必须更新订阅）、**删除**（只删面板里的记录，代理本身不动；想让它停止服务，先停用再删除）。连不上时会给出原因（节点路径或密钥不对、代理没设置 `NODE_KEY` / `NODE_KV`、Cloudflare 错误 1042 / 1024 等），记录仍会保存，改好后点「连接并同步」。

没有启用的代理或缺 UUID 时，面板顶部会提示，订阅与预览返回「订阅还不能生成：缺少……」。连接成功后，在 **仪表盘 → 订阅地址** 复制对应客户端的订阅链接并导入；再到 **优选配置** 里按需开关优选 IP 来源、编辑优选域名。

| 入口 | 地址 | 说明 |
|---|---|---|
| 面板 | `https://面板域名/<PATH>` | 需登录（用户名 + 密码）；`PATH` 未设置或格式不对时所有请求返回设置说明（503）；未设置 `ADMIN` 时面板提示「已禁用」 |
| 订阅 | `https://面板域名/<PATH>/sub` | 按客户端 UA 自动识别格式；追加后缀强制指定，如 `/sub/clash`、`/sub/singbox`；也可以用「自定义订阅路径」别名 |
| 配置 API | `https://面板域名/<PATH>/api/config` | GET 读取 / POST 保存，支持只提交部分字段；需登录 |
| 代理 API | `https://面板域名/<PATH>/api/proxies` | 代理列表的增删改与 `/<id>/sync`、`/<id>/enabled`、`/<id>/rotate`；另有 `/api/proxy-status`、`/api/proxy-settings`、`/api/proxy-reset`；需登录，密钥只写不读 |
| 节点 | `wss://代理域名/<节点路径>` | 由代理处理，面板只负责生成指向它的链接 |

### 2.5 Pages 部署（可选）

1. 控制台 → Workers 和 Pages → 新建 **Pages 项目**（直接上传）
2. 上传目录里放入对应脚本，框架选「无」；Pages 的高级模式要求文件名为 **`_worker.js`**，上传时请改名
3. 在 Pages 设置里添加对应脚本的环境变量；面板还需绑定 KV（变量名 `CONFIG_KV`）

### 2.6 更新

1. 取最新的脚本，**覆盖粘贴**到对应的 Worker 里并部署；环境变量与 KV 里的配置原样保留，无需重新设置。两个脚本**各自编号**（文件顶部横幅 `/*!Hopline-panel vX.Y.Z*/` 与 `/*!Hopline-proxy vX.Y.Z*/`），更新节奏不同，可以分别更新；它们之间只通过 `vless://` 链接与签名的控制接口联系；同一个 3.1 系列的面板与代理互相配套（控制接口的协议两边一致），建议一起更新；代理脚本很少需要更新
2. 面板里点击版本号可检测更新：读取仓库 `main` 分支的 `Hopline-panel.js` 比对版本号，有新版本时把它的内容复制到剪贴板（只检测面板脚本；代理脚本的版本在仪表盘「运行状态 → 代理状态」里查看）。提示「仓库 main 分支上没有 Hopline-panel.js（HTTP 404）」说明这个文件还不在 `main` 上——新版本尚未合并发布，或仓库不是公开的（`raw.githubusercontent.com` 不带凭据，私有仓库一律 404）

### 2.7 从 2.x / 3.0.x 升级

3.1 把 UUID 交给面板管理、用签名 HTTPS 取代服务绑定，**没有就地升级路径**（不兼容变更），请按全新部署处理：

1. 代理 Worker：换成 3.1 的 `Hopline-proxy.js`；环境变量只留 `PATH`，新增 `NODE_KEY`，绑定 `NODE_KV`；原来的 `UUID` 环境变量不再被读取（可以删除）；反代 / 落地 / 出站等可选变量照旧
2. 面板 Worker：换成 3.1 的 `Hopline-panel.js`；删除服务绑定 `PROXY`，以及环境变量 `HOST` / `UUID` / `NODE_PATH`（不再读取）；面板配置（优选 / 筛选 / ECH / 管理密码）原样保留
3. 在「面板设置 → 代理」添加代理（域名、节点路径、`NODE_KEY` 的值），点「保存并连接」：面板生成新的 UUID 并下发，订阅里的节点随之使用新 UUID，**客户端需要重新更新订阅**
4. 想继续使用旧 UUID：保存前把旧 UUID 填进面板的 UUID 栏，连接时会把它下发给代理

### 2.8 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面只显示 `Hello World !` | 访问路径不对。面板入口必须是 `https://面板域名/<PATH>`；代理上除节点路径外的任何路径都显示这个页面 |
| 所有请求返回「设置说明」（503） | 面板：`PATH` 没设置或格式不对；代理：`PATH` 或 `NODE_KEY` 没设置或格式不对（`NODE_KEY` 至少 24 位可见字符），按提示修改后重新访问 |
| 面板提示「已禁用」 | 没有设置 `ADMIN` |
| 保存时报错 / 无法保存 | 面板没有绑定 KV，变量名必须是 `CONFIG_KV`（代理列表也保存在这个 KV 里） |
| 面板顶部提示「还不能生成订阅，缺少……」 / 订阅返回 400 | 到「面板设置 → 代理」添加代理并点「保存并连接」；提示「启用中的代理」说明现有代理都已停用 |
| 节点连不上 | 在仪表盘点「检测代理」：看代理是否在线、UUID 是否与面板一致（不一致点「连接并同步」）、代理是否被停用；检查代理域名是否与代理 Worker 的自定义域名一致 |
| 检测更新提示「仓库 main 分支上没有 Hopline-panel.js（HTTP 404）」 | 该文件不在仓库 `main` 分支上：3.x 的拆分版本还没有合并到 `main`，或仓库是私有的。合并发布后即恢复；在此之前可直接从对应分支取脚本部署 |
| 仪表盘「代理状态」显示「无法连接」 | 看提示原因：「没有响应控制请求」= 节点路径或密钥与代理的 `PATH` / `NODE_KEY` 不一致（或代理脚本版本过旧）；「错误 1042」= 面板与代理在同一个 zone，代理要用 Custom Domain；「错误 1024」= 域名填成了 IP；「无法连接代理」= 域名解析或证书问题、代理 Worker 没有绑定该自定义域名 |
| 「代理设置」页提示代理没有绑定 KV | 给**代理 Worker** 绑定一个单独的 KV 命名空间，变量名 `NODE_KV`，再到「面板设置 → 代理」点「连接并同步」 |
| 「代理设置」页提示没有代理 | 先到「面板设置 → 代理」添加并连接代理 |
| 在「代理设置」页保存后代理没变化 | 约 1 分钟内生效（KV 同步与缓存）；仪表盘「检测代理」的摘要会显示代理当前生效的设置 |
| 客户端更新订阅提示「无效订阅」 | `*.workers.dev` 域名可能被限制，给面板绑定自定义域名，或让客户端通过代理更新订阅 |
| 登录后过一段时间被退出 | 24 小时未使用面板自动退出，最长 7 天需重新登录 |
| 改了代理的 `PATH` 或 `NODE_KEY` 后节点连不上 / 面板连不上代理 | 同步修改面板里的「节点路径」或「密钥」，再点「连接并同步」；改了节点路径后客户端需要更新订阅 |

## 三、环境变量与配置项

### 3.1 代理脚本（`Hopline-proxy.js`）的环境变量

> 代理没有面板：**环境变量必填只有 `PATH` 与 `NODE_KEY`**，另需绑定 KV `NODE_KV`（保存面板下发的 UUID、启用开关与在线设置）。未设置的可选项取下表默认值，行为与 2.x 版面板里的默认设置完全一致；无效取值按默认值处理。VLESS 的 WebSocket 与 XHTTP 两种传输始终同时启用。

| 变量 | 值 | 说明 |
|---|---|---|
| `PATH` | 节点路径 | **必需**，WebSocket / XHTTP 共用此路径；只能含字母、数字及 `. _ ~ -`，最长 128 位，首尾的 `/` 自动去掉。面板里「节点路径」必须与它一致 |
| `NODE_KEY` | 控制密钥 | **必需**，24–256 位可见 ASCII 字符。面板用它给控制请求签名并验证代理的回应，控制入口的路径也由它派生。面板里「密钥」必须与它一致 |
| `EDGEIP` | `host` 或 `host:port` | 反代 / 落地 IP：填写后作为固定出口优先使用；留空则直连失败后由地区反代兜底 |
| `HOP_ADDR` | `socks5://` / `http(s)://` / `ss://` 地址，或 `user:pass@host:port` | 出站代理（SOCKS5 / HTTP(S) / Shadowsocks）；SS 加密支持 aes-128-gcm / aes-256-gcm / chacha20-ietf-poly1305 |
| `HOP_MODE` | 留空 / `no` / `only` | 出站方式：留空（默认）= 出站代理优先，失败后直连 ∥ 反代；`no` = 直连 ∥ 反代优先，都不通时最后用出站代理；`only` = 仅走出站代理（失败用地区反代兜底，地区反代为 `off` 时不兜底）。未填出站代理时三种方式都按直连处理 |
| `ALT_MODE` | `builtin` / `custom` / `off` | 地区反代：`builtin`（默认）= 内置 proxyip.\*.cmliussss.net，按 Worker 机房自动选地区；`custom` = 只用 `ALT_CUSTOM`；`off` = 不使用，只直连 / 出站代理 |
| `ALT_REGION` | `HK` `US` `SG` `JP` `KR` `DE` `SE` `NL` `FI` `GB` `Oracle` `DigitalOcean` `Vultr` `Multacom` | `builtin` 的首选地区（取 2 个 IP）；留空按机房自动选，不区分大小写 |
| `ALT_REGION2` | 同上，或 `none` | `builtin` 的次选地区（取 1 个 IP）；留空 = 默认的另一地区（首选为 HK 时用 US，否则用 HK），`none` = 只用首选 |
| `ALT_CUSTOM` | 最多 3 个 `host[:port]` | `custom` 的反代列表，换行或逗号分隔，IPv6 需加方括号；第一个取 2 个 IP，其余各取 1 个。「反代 / 落地 IP」仍然优先于这里 |

**面板下发的状态与在线修改（`NODE_KV`）**：代理的 UUID、启用开关与 7 项设置覆盖项都保存在 `NODE_KV` 的 `state` 里，由面板通过控制接口写入。设置优先级：**KV 里保存的设置 > 环境变量 > 默认值**；与环境变量相同的值不会存入 KV（改环境变量立即生效）；「恢复为环境变量」只清除设置覆盖项，不动 UUID 与启用开关。KV 读取有约 20 秒的内存缓存 + KV 边缘缓存，保存后约 1 分钟内全部实例生效（写入的那个实例立即生效）；只有节点路径上的连接才会读取 KV，读取失败时沿用上次读到的状态，不会阻断代理；KV 读不到时拒绝所有写操作，不会覆盖已有状态。出站代理里的用户名与密码会以明文存在这个 KV 里，所以请不要把它和别的数据共用。

**控制接口协议**（面板与代理共用同一份实现）：`POST /<PATH>/<标记>`，标记由 `NODE_KEY` 派生；请求体 `{ts, n, op, a, s}`，`s = HMAC-SHA256(NODE_KEY, ts.n.op.a)`，时间偏差不超过 30 秒、同一个随机串 `n` 只接受一次；回应 `{ts, d, s}`，`s = HMAC-SHA256(NODE_KEY, ts.n.d)`（绑定了请求的 `n`，面板据此确认回应来自持有密钥的一方）。操作：`status` / `getSettings` / `setSettings` / `resetSettings` / `setIdentity`（下发 UUID，轮换时旧 UUID 保留 10 分钟）/ `getIdentity` / `setEnabled`。任何一步不合规都返回与其它路径一样的 `Hello World !`。

> `UUID`（现在由面板下发）以及 `HOST`、`ENABLE_ECH`、`ALPN`、`ADMIN`、`ADMIN_USER`、`CONFIG_KV` 等变量，代理都不读取。

### 3.2 面板脚本（`Hopline-panel.js`）的环境变量

> 优先级：**KV 配置 > 环境变量 > 默认值**。环境变量只在面板里没有改成别的值时生效：面板保存时，与环境变量相同的值不会写入 KV（之后修改环境变量立即生效），改成不同的值才保存为覆盖。`PATH`、`ADMIN`、`ADMIN_USER` 设置后在面板中只读。**必填只有 `PATH` 与 `ADMIN` 两项**。

| 变量 | 值 | 说明 |
|---|---|---|
| `PATH` | 访问路径 | **必需**。面板与订阅（`/<PATH>/sub`）的访问路径；只能含字母、数字及 `. _ ~ -`，不能是 `login`、`version`；首尾的 `/` 自动去掉。**与代理的节点路径互相独立** |
| `ADMIN` | 管理密码 | **必需**，未设置时面板与管理接口一律禁用 |
| `ADMIN_USER` | 管理用户名 | 可选，登录时与密码一起校验（区分大小写），默认 `admin` |
| `CONFIG_KV` | KV 命名空间绑定 | 可选（推荐），在 Worker / Pages 设置里绑定 KV 命名空间时使用的变量名；绑定后面板配置与代理列表（域名、节点路径、密钥、UUID、启用开关）才能保存 |
| `ENABLE_ECH` | true / 1 | 启用 ECH 加密客户端握手（开启后自动仅 TLS 端口） |
| `ALPN` | h2 / http/1.1 | ALPN 协商（逗号分隔），VLESS / XHTTP 链接、Clash、Sing-box 均按此下发；留空时 ws 用 http/1.1、XHTTP 用 h2 |

### 3.3 面板配置项（保存于 KV，也是 `/api/config` 的字段名）

> 完整字段、默认值与校验规则以 `src/worker/config-schema.js` 中的 `CONFIG_SCHEMA` 为准。代理（域名 / 节点路径 / 密钥 / UUID / 启用）不在这里：它们保存在 KV 的 `proxies`（数组，最多 8 项）里，通过 `/api/proxies` 管理，不属于面板配置，也不在导出 / 重置的范围内。保存时逐项校验，未登记的字段会被忽略（旧版本留在面板 KV 里的 `proxyIP` / `outboundProxy` / `outboundMode` / `relay.*` 即属此类）。嵌套字段用 `a.b` 表示，接口里是 `{ "a": { "b": … } }`。

| 配置项 | 说明 |
|---|---|
| `adminUser` / `admin` | 管理用户名 / 管理密码（同环境变量，面板可视化编辑；`admin` 只写不回显） |
| `subUrl` | 自定义订阅路径：`/<别名>/sub` 输出订阅（别名下不开放面板与管理接口）；留空为 `/<PATH>/sub`。面板路径下的 `/sub` 始终可用 |
| `enableVless` / `enableXhttp` | 订阅里是否下发 VLESS / XHTTP 节点（默认均开；只是下发开关，代理始终两种都接受） |
| `alpn` / `tlsOnly` | ALPN 协商 / 仅 TLS 端口节点（默认开启；关闭后 443 节点追加 80 明文节点） |
| `ech` / `echHost` / `echDns` | ECH 开关 / 自定义 ECH 域名 / ECH DoH |
| `filter.region` | 地区（多选数组）：`['all']` 或 HK / TW / US / SG / JP / KR / DE 的组合 |
| `filter.ipType` | IP 版本：IPv4 / IPv6（默认只有 IPv4） |
| `filter.isp` | 运营商：移动 / 联通 / 电信 |

| `ipsrc.hostmonit` / `ipsrc.uouin` / `ipsrc.wetest` / `ipsrc.api1` / `ipsrc.api1Url` / `ipsrc.api2` / `ipsrc.api2Url` | 优选 IP 来源开关（HostMonit / uouin / 微测网 / 自定义 API 1 / 2）与两个自定义 API 地址（默认：HostMonit 开、uouin 开、微测网关、自定义 API 关；开启 API 但未填地址时保存会报错） |

## 五、地址来源与优选

### 5.1 地址来源

默认节点池由「仪表盘 → 地址来源」三项组装：

| 来源 | 说明 |
|---|---|
| **原生地址**（默认关） | 代理域名直接作为节点下发 |
| **优选域名**（默认开） | 直接下发域名，客户端连接时自行解析到当前最优的 Cloudflare 边缘 IP；列表可在「优选配置 → 优选域名」自定义（整体替换内置列表，留空用内置的 14 个）。IPv6 解析：同时勾选 IPv4 与 IPv6 时只解析前 12 个域名，仅 IPv6 时前 25 个 |
| **优选 IP**（默认开） | 「优选配置 → 优选 IP 来源」中开启的在线来源，见下表 |

### 5.2 在线优选 IP 来源

| 来源 | 默认 | 说明 | 节点名示例 |
|---|---|---|---|
| 自定义优选 API 1 / 2 | 关 | 填写返回 IP 列表的地址（纯 IP 行 / CSV / HTML 线路表 / base64 订阅 / `sub://`，行内可写 `IP:端口#名称`）；开启但未填地址时保存会报错 | 数据行里的名称原样保留 |
| HostMonit（`api.hostmonit.com`） | 开 | 分运营商实测的实时优选；接口失效时沿用上次结果，由其它来源兜底 | 移动-01 / 联通-01 / 电信-01 |
| uouin（`api.uouin.com`） | 开 | 电信 / 联通 / 移动 / 多线 / IPv6 各约 10 个 IP。使用的是对方网站的内部接口（非开放 API，签名模仿其网站前端），对方可能随时更换签名或封禁，届时静默失效 | 电信-U01 |

- 排列顺序：自定义 API 1 / 2 → HostMonit → uouin → 微测网
- 结果缓存 10 分钟（绑定自定义域名时，同一机房的实例通过 Cache API 共享缓存；workers.dev 下 Cache API 不生效，各实例各自缓存），缓存未命中时每个开启的来源占用 1 个子请求
- 所有来源一律只保留 Cloudflare 段 IP，其余丢弃：非 CF 段的第三方中转 IP 可获知部署域名与连接元数据，无法作为入口

### 5.3 节点命名与地区

- 同时开启多种协议时，同一地址的 XHTTP 节点名加「.X」（VLESS 保持原名）；不同地址同名时依次加「·2」「·3」，所有格式的节点名唯一
- 优选域名节点命名为「优选域名-XX」；优选 IP 来源中无法确定地区的统一为「优选IP-XX」（IPv6 域名解析结果为「优选IP-V6-XX」）；数据源自定义名称（如 `JP-A-147`）原样保留
- 带地区标记的数据行（如「IP:端口#地区随机 \| 香港 HK」）显示中文地区名：香港 / 台湾 / 日本 / 美国 / 新加坡 / 韩国 / 德国
- 「节点地区」筛选只剔除名称明确标记为其它地区的节点。内置来源都是不带地区的 Cloudflare 任播 IP / 域名（落地机房取决于客户端网络），地区筛选通常不改变其节点构成；需要按地区挑选请让自定义优选 API 返回带地区名的来源

### 5.4 自己测速

面板不提供在线测速。请用本地测速工具在自己的网络下测速，把结果托管成一个地址（纯 IP 行 / CSV，行内可写 `IP:端口#名称`），填入「优选配置 → 优选 IP 来源」的自定义优选 API 1 / 2。

## 六、性能与安全

### 6.1 性能

- **低 CPU 的数据面**：XHTTP 数据由运行时原生管道转发（JS 只处理握手）；WebSocket 下行用 64KB 缓冲的 BYOB 读取，一次取走已到达的全部数据（最多 64KB）作为一条消息发出（读取次数约为默认读取的 1/16，每 MB CPU 约为原来的 1/5），并拒绝压缩，避免看视频时触发 `Worker exceeded CPU time limit`
- **DoH 与子请求预算**：优选域名解析 Cloudflare DoH 优先，仅当请求失败时降级阿里 DNS，正常每次解析只计 1 个子请求（代理侧的反代域名与 UDP DNS 解析同样 Cloudflare 优先、逐个降级，超过 0.7 秒未响应会提前并发下一个）；IPv4+IPv6 混合时只对前 12 个优选域名查询 AAAA。实测单次订阅约 14–20 个子请求，最坏（仅 IPv6、30 个自定义域名、全部来源开启）约 31 个，低于免费版上限 50
- **出站并发竞速**：直连与地区反代（内置或自定义，可用 `ALT_MODE=off` 关闭）同时发起，取先握手成功的一路，败者连接立即释放；直连有 1.5s 优先窗口（可直连的站点不绕第三方反代）；目标为 Cloudflare IP 时不发直连、直接用反代；直连失败、由反代接通的站点会被记住 30 分钟，之后直接走反代（不再发直连、不查 DNS）。目标站在 Cloudflare 上时不再白等约 6 秒；出站模式（默认 / 直连优先 / 仅走代理）决定出站代理与直连、反代的先后
- **首包判定**：地区反代与「反代 / 落地 IP」只能转发 TLS 流量（按 SNI 路由），非 TLS 首包（Telegram MTProto、明文 HTTP 等）只走直连与出站代理
- **WS 0-RTT 早数据**：TLS WebSocket 节点带 `?ed=2048`（Sing-box 用 `max_early_data`），客户端把首包放进握手请求头，服务端握手时即建连，省约 1 个往返；早数据校验不通过时按普通连接处理
- **VLESS 响应头提前下发**：头部解析成功即回 2 字节响应头，首包等待上限 80ms，避免与部分客户端（mihomo 等）互相等待
- **SWR 容灾缓存**：外部优选源拉取失败时沿用上一轮有效结果（10 分钟缓存；绑定自定义域名时同一机房共享）

### 6.2 安全

- **管理登录**：必须设置 `ADMIN`，以用户名 + 密码登录（任一错误都只提示「用户名或密码错误」）；KV 中的密码保存为加盐 PBKDF2 摘要（环境变量 `ADMIN` 本身是明文）；登录失败 15 分钟内最多 5 次，IPv6 按 /64 计数
- **会话**：24 小时无操作失效（使用时自动顺延，最长 7 天），可在「面板设置」退出；修改管理密码或用户名会使其它浏览器的登录状态全部失效（代理列表与登录无关）
- **页面安全头**：面板与登录页带 CSP、`X-Frame-Options`、`nosniff`、`Referrer-Policy`；二维码脚本带 SRI 校验
- **内嵌页面**：面板页面、登录页与 Clash 模板都内嵌在 `Hopline-panel.js` 里，运行时不从 GitHub / jsDelivr 拉取任何代码或页面，没有第三方内容被当作页面执行（浏览器只加载带 SRI 校验的二维码脚本）
- **路径与 UUID 鉴权**：面板脚本里请求路径与 `PATH` 一致才进入面板；代理脚本里请求路径与 `PATH` 一致才进入代理，VLESS 头部的 UUID 与面板下发的 UUID（轮换后的旧 UUID 仅在 10 分钟宽限期内）一致才转发；订阅别名路径只输出订阅
- **路径伪装**：路径不对（根路径、未知路由）时两个脚本都返回 200 的 `Hello World !` 页面，不暴露部署；面板的 `/login`、`/version` 只对知道面板路径的人可用，否则返回 404。代理上没有 `/login`、`/api`、`/sub` 等任何路由，也看不出它和面板有关
- **控制接口签名、防重放、不暴露**：面板与代理之间只有签名的 HTTPS 请求（HMAC-SHA256，密钥 `NODE_KEY`）：入口路径由密钥派生，30 秒时间窗 + 一次性随机串防重放，回应同样签名并绑定请求的随机串，面板据此识别冒充；任何不合规的请求都返回 `Hello World !`，不泄露这里有入口；代理的任何公开响应里都没有版本号。状态只返回在线 / 版本 / 配置问题 / 是否已下发 UUID / 是否启用 / 设置摘要（有无反代 IP、出站代理的类型、模式、地区、自定义反代个数），不含 UUID（只有短标记）、路径、密钥、反代地址与出站代理的主机和密码；`getIdentity` 只对持有密钥的面板开放。密钥在面板里只写入、不回显，不进入配置导出；它保存在面板的 KV 里，请像保护管理密码一样保护这个 KV
- **拆分带来的隔离**：代理脚本不含面板、登录、订阅与管理接口的任何代码，也不访问 GitHub；面板脚本不含任何代理代码（没有 `cloudflare:sockets`、WebSocket 与出站连接）。两者只通过 `vless://` 链接和签名的控制接口联系，没有服务绑定，可以在不同的账号里
- **Clash 本地凭据**：订阅里的 Shadowsocks 入站密码、认证与 API secret 按 UUID 为每个部署派生，不使用公开的默认密码
- **配置存储保护**：配置读取走 KV 边缘缓存（30 秒）；KV 读取失败或配置损坏时拒绝保存，面板与订阅按环境变量 + 默认值工作，避免用默认值覆盖已有配置

### V2.4.4

- **WebSocket 下行 CPU 约降为原来的 1/5**：目标连接改用 64KB 缓冲的 BYOB 读取，一次取走已到达的全部数据（最多 64KB）作为一条消息发出，不再按约 4KB 逐块读取、也不再用 0ms 定时器探测后续数据。workerd 实测 64MB 下行：读取次数 16522 → 1040，每 MB CPU 约 5.9ms → 1.2ms，吞吐约 2.5 倍；看视频等大流量更不容易触发 `Worker exceeded CPU time limit`
- 发出的缓冲不再交给下一次读取（`ws.send()` 不会立即复制数据，复用缓冲会损坏数据）；SS 出站的解密流不支持 BYOB，继续使用原有的合并读取
- 上行（客户端 → 目标）合并写入经实测没有收益（CPU 花在运行时逐条分发 WS 消息上），保持不变
- `obf_Hopline.js` 同样受益：数据面文件只做改名与压缩空白，实测与 `Hopline.js` 的下行 CPU、吞吐一致
